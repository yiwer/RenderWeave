# ADR-0017：超大设计图在服务端有界缩放后进入推断

> 2026-08-10：ADR-0024 将 Provider 规范化产物进一步收窄为最长边 ≤4096 且总像素 ≤16000000；费用预留仍保留原 4096² 保守上界。

- 状态：Accepted
- 日期：2026-08-10
- 决策来源：用户要求将实际设计图排队识别；原请求通过网关后被旧 4096 源尺寸边界以 422 拒绝
- 关联：AC-015、AC-019、AC-020、ADR-0008、ADR-0016、P6/T6-3a.3

## 背景

4096 是 Provider 输入、费用保守估算和证据画布的规范化上限，不应等价为要求用户在上传前手工缩图。
直接删除尺寸限制又会让高度压缩的 PNG/JPEG 形成不可控解码工作集。因此产品需要区分“源图安全边界”
和“持久化/Provider 规范化边界”。

## 决策

1. 保留单图 10 MiB、批次 30 MiB、PNG/JPEG magic、动画拒绝和显式外发确认。
2. 源图允许最长边至 65535、总像素至 268435456；超过任一硬门仍以
   `INFERENCE_IMAGE_DIMENSIONS_INVALID` 零任务拒绝。
3. ImageIO 只先读取 header。预计完整解码超过 20000000 pixels 时设置等比 source subsampling，
   再用高质量插值将可解码结果缩放到最长边不超过 4096；常见的 4097 或截图长图保持高质量缩放。
4. EXIF orientation、sRGB 转换、metadata 清除和规范 PNG 编码继续发生在持久化之前；原始 bytes 不持久化。
5. artifact width/height、Provider 输入与 Candidate 图片 evidence 坐标统一指向规范化产物，费用估算仍使用
   4096² 最坏边界，不因接受更大源图而放宽。

## 后果

- 用户可直接提交常见高分辨率设计图，不再因源图最长边略高于 4096 手工缩图。
- 极端 header/像素炸弹仍 fail-closed；subsampling 是资源边界，不是对任意大图的无限支持承诺。
- 规范化可能减少极细小文字细节，因此 Profile 继续为 `EXPERIMENTAL`，审核界面仍需让用户核对 Candidate。
- 回退可恢复旧源尺寸拒绝逻辑；数据库与已持久化 artifact 无需迁移或重写。
