# ADR-0019：图片证据坐标规范化与候选审核信息密度

- 状态：Accepted
- 日期：2026-08-10
- 决策来源：真实 IMAGE_ONLY Candidate 的证据框与规范化图片明显错位；用户要求检查原因并优化候选数据结构展示
- 关联：AC-017、ADR-0014、ADR-0017、ADR-0018、P6/T6-3a.5

## 背景

Candidate 合同规定图片 bbox 是规范化图片上的 0..10000 整数坐标。一次真实输出却返回了规范化产物的
像素坐标：图片为 1510×4096，多个框均落在该像素边界内，且最后一个框到达 4096。因为这些像素值也
小于 10000，原 validator 无法只凭单框区分两种坐标空间；Web 按合同除以 10000 后，框被压缩到图片左上角。

审核页同时逐条横向展示重复 WARNING，单 Schema 仍占用排序列，字段卡片缺少稳定列语义，使用户难以快速
区分字段定义、推断来源、置信度和审核状态。

## 决策

1. Candidate 的权威合同保持不变：持久化和 API 中的图片 bbox 仍为 0..10000，越界或反向坐标仍由
   validator 阻断，不放宽 Provider 输出合同。
2. `IMAGE_ONLY` 在严格 validator 前可对“明确为像素坐标族”的证据做确定性换算。判定必须同时满足：
   同一 artifact 至少两个 bbox；所有 bbox 合法且位于 artifact 像素边界内；bbox 并集横纵均覆盖至少
   50% 画布、起点不晚于 30%、终点不早于 70%；右侧或底部到达 artifact 尺寸的 98%。
3. 命中后按 artifact width/height 换算为 0..10000；left/top 向下取整、right/bottom 向上取整以避免
   缩小证据覆盖。每个被修改的 assessment 记录
   `IMAGE_EVIDENCE_PIXEL_COORDINATES_NORMALIZED` WARNING。
4. 单框、未触达右/下边界或其他模棱两可的集合不猜测、不换算。缺失图片尺寸时也保持原合同路径。
5. Web 使用同一保守判定仅做历史 Candidate 的显示兼容，不改写既有 revision；命中时显示“像素坐标已换算”。
   新 Candidate 已由服务端持久化为规范坐标，因此不会再次命中。
6. 全局诊断按 severity + code 聚合为可换行摘要，保留数量并定位首个相关项；不再产生横向诊断带。
7. 单 Schema 隐藏无意义的排序列；字段表单固定为“字段 / 类型与约束 / 来源与置信度 / 审核”四个信息区，
   证据框增加可读标签。多 Schema 的键盘排序与 1180px Inspector drawer 合同保持不变。

## 后果

- 当前历史审核任务无需重试或再次调用模型即可正确显示；未来同类输出会在持久化前变成规范坐标。
- 这是受限兼容层，不是通用坐标猜测器。未满足完整判定的历史像素框仍可能按合同显示，需人工识别；宁可
  保留歧义，也不静默改写可能合法的 0..10000 数据。
- 换算只改变坐标表示，不改变 artifact、证据语义、字段身份、类型、置信度、resolution 或图拓扑。
- 真实业务图片和浏览器截图不写入仓库证据；回归使用合成坐标族与合成图片尺寸。
