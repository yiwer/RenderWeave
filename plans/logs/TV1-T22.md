## 产品增量

1. 新增独立 `renderer/` Cargo workspace，不进入 Maven reactor；固定 Rust 1.89.0、edition 2024、
   `Cargo.lock`、仓库内 vendor 与 offline Cargo 配置。`process-manifest.json` 是 exact machine identity，明确
   空 renderer profile 集合、`NOT_REGISTERED`、`NOT_CERTIFIED` 与 Linux production target policy。
2. Rust/Java 共同实现 `renderweave-renderer-process/1.0`：typed length-prefix frame、strict canonical JSON、
   canonical UUID v4、四位年 RFC3339 UTC 毫秒、RenderDocument/Command domain-separated digest、closed
   hello/command/cancel/result/problem shape，以及 result image length/SHA-256 完整性检查。
3. Rust daemon 仅在 Linux 运行，创建 0600 UDS、保持单 app connection 与内存 request registry；同
   requestId/command digest 重放 exact terminal outcome，异 digest 冲突，cancel 保留 tombstone。由于没有已注册
   raster Profile，合法 Command 稳定返回 `RENDER_INTERNAL_ERROR` terminal problem，零 image/partial output。
4. app 新增 production `RendererProcessAdapter` 与 `RendererProcessSupervisor`：persistent session、同步写、
   reader dispatch、完整 outcome 映射、断连/不确定提交返回 Unknown、Unknown exact retry 使用新连接。Supervisor
   仅接受预配置且无 symlink traversal 的 POSIX 0700 socket parent，拒绝自建部署目录与预存 socket；只有显式
   executable/socket/manifest 配置才装配 bean，默认保持 fail-closed。
5. 新增共享 exact vectors、独立 Python verifier 与 `render` gate；gate 固定 Rust 工具链，执行 fmt、clippy
   `-D warnings`、locked/offline workspace tests、Java primary tests、独立 replay，并在 `rust:1.89-slim`
   `--network none`/只读源码挂载中实际完成 Linux UDS round-trip。`full` 从 16 steps 扩为 17 steps。
