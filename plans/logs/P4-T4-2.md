## 关键结果

- `InferenceProfileRegistry` 只暴露 `replay-v1`；资源明确声明 `provider=REPLAY`、`networkAllowed=false`、三模式、8000 bps 低置信阈值、最多 2 轮 repair 与 2 MiB 输出上限。
- JSON 样本在 normalize 阶段转换为 `renderweave-json-profile/1.1`：数组 occurrence 归并为 `/*` 路径，只保留 pointer/kind/count/evidence pointer，不保留原始 value；跨样本 profiler 再生成确定性 observation。
- JSON 推断不自动添加 required、min/max/enum/constraint；嵌套 object 与 object array 生成独立 CandidateSchema，object array 取字段并集且字段保持 optional，不按 shape 自动复用 Schema。
- scalar 类型冲突降级 TEXT + warning；object/array/scalar 冲突、全 null、空数组、嵌套数组和异构数组进入 blocker；concrete+null 保留具体类型但逐项 unresolved。
- Candidate 与正式 DSL 是不同 Java 类型；CandidateSchema/CandidateField 使用 run-local opaque UUID 维持审核/evidence 身份，正式字段身份仍是 `SchemaKey + fieldKey`，没有引入正式 `fieldId`。
- image evidence 使用归一化图片 artifactId + 0..10000 bounding box；JSON evidence 使用 sample index + JSON Pointer。低置信项分别携带 `UNRESOLVED`，不存在 confirm-all 状态或操作。
- combined 模式以 JSON concrete structure/type 为准；图片可补 display name/evidence，并只把 JSON TEXT 细化为 DATE/TIME；不兼容视觉类型以 `VISUAL_TYPE_CONFLICT_IGNORED` 留给审核，绝不覆盖 JSON 结构。
- 60 例 manifest 固定为 image/json/combined 各 20 例，覆盖 Unicode key、null/array/object 边界、提示注入值、多图片、低置信、required 建议、类型冲突与 1/2 轮 repair；所有案例通过 strict Candidate round-trip、证据覆盖、值不泄漏和 run ID 隔离检查。
- V006 只增加 `inference_candidate` 与安全 attempt metadata；不保存 prompt、原始素材、样本值、完整模型输出或 chain-of-thought。original/current Candidate 以 revision 0 同时创建。
- worker 按 `OBSERVE → STRUCTURE → DETERMINISTIC_VALIDATE → CRITIQUE → REPAIR(≤2) → USER_APPROVAL` 执行；attempt 与 stage checkpoint 同事务，lease 过期后从最后完成阶段继续，不重复已提交 attempt。
- `CRITIQUE → REVIEW_REQUIRED` 与 Candidate revision 0 在同一 PostgreSQL 事务完成；即使 Candidate 含 unresolved/conflict blocker 也可安全进入人工审核，但 worker 没有 Schema repository 依赖，测试证明 Draft/Static 行数不变。
- cooperative cancellation 在下一个 stage boundary 确认，取消 run 不产生 attempt、Candidate 或 Draft。

## 重要取舍

- replay visual observation 来自版本化 synthetic fixture，不伪装成 OCR/vision 模型；真实 provider adapter 与 live quality certification 仍属于未授权 P5。
- repair 只重放确定性、显式声明的 invalid-output fixture；attempt 表只记 ordinal/stage/status/outcome code，避免把 provider I/O 或不可信内容写入日志/数据库。
- T4-2 不开放 Candidate HTTP 编辑面，也不 materialize Draft；Candidate review API/UI 属于 T4-3，create-only atomic apply/SSE 属于 T4-4。
