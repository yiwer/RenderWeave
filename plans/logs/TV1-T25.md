## 产品增量

1. 新增 workspace-internal `renderweave-renderer-layout` deep kernel。唯一入口
   `preflight_layout(&AdmittedRenderDocument)` 强制调用方先跨过 T23 strict document admission；内部仅重解析
   immutable canonical bytes，返回 `LayoutPreflight` counts 或一个 closed `LayoutProblem`。
2. kernel 按 materialized authored DFS 验证 `renderweave-layout/1.0` 的 kind/size-mode、FIXED 正值与 min/max、
   Image 双 HUG、Group 双 HUG且无 min/max、Frame/Group/Stack HUG→child FILL cycle、Stack fillWeight、Grid
   row/column/span、64-track capacity、HUG/FRACTION、FILL/AUTO、track 正值、Text `VISIBLE + maxLines` 与双
   FIXED QR exact square。
3. 数值只接受 canonical plain decimal6，使用 checked `i128`，拒绝 exponent、超过六位小数、负零与溢出；
   没有选择或暗示 binary64 tolerance，也没有进入 measure/arrange。
4. `LayoutPreflight` 只公开 occurrence、tree edge、max depth、Grid、track、cell counts；stable problems 仅公开
   `LAYOUT_CONSTRAINT_INVALID | LAYOUT_CYCLE | LAYOUT_NUMERIC_ERROR | LAYOUT_BUDGET_EXCEEDED`、occurrence、
   property 和 closed capacity `limitId`。没有 box、scene、glyph、resource、paint item 或 trace。
5. daemon 在 document admission 后、Profile lookup 前调用 preflight；失败折叠为
   `RENDER_INTERNAL_ERROR`/`DOCUMENT_ADMISSION`，通过后仍由空 Profile registry 在
   `COMMAND_ADMISSION` fail closed。没有 RESULT、partial scene 或 output path。
6. `render` gate 升至 1.2，新增 layout independent report及冻结 counts/boundary assertions，并继续在 Windows
   Rust workspace与 pinned no-network Linux Docker/实际 UDS 中重放。Cargo.lock identity 已传播到 exact
   process manifest与 HELLO vectors，但没有新增 capability 或 Profile。
