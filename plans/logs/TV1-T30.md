   owner scope、target Template、permanent StaticSchema、expected revision、proposed content、完整 problems 与 exact
   dependency snapshot；无 generic force，也不把 token 送入 DesignDSL。
3. create/save/readiness recheck 均把 dependency snapshot 带入 persistence fence。正常 READY save 在 commit drift 时最多
   重新求值三次；confirmed INVALID 遇到任一 dependency/current/problem drift 永远零写，仅在 fresh problem set 仍完整
   可确认时签发替代 token。revision conflict 与 outcome-unknown 继续遵守 E3 合同。
4. PostgreSQL V025 持久化单次 confirmation claims；production authority 以随机 64-hex token、过期清理和 atomic consume
   实现。Template append/create 在 SERIALIZABLE transaction 中锁定并核对所有现存 Asset/Template facts；missing-row
   predicate 或任一 identity/revision/readiness/content/lifecycle 漂移均 rollback。
5. Controller/OpenAPI/generated SDK 统一到 contractVersion `0.15.0`，422 closed outcomes 区分 required、invalid、expired、
   stale 与 hard rejection，503 对 dependency/confirmation persistence unavailable fail closed。隔离 Spring composition
   缺少 Host authority 时保留 fail-closed fallback，正式应用注入 PostgreSQL authority。
6. Web offer 绑定 token、expectedRevision、exact draft canonical、preview generation、problems 与 expiry；edit/undo/redo/
   conflict-current drift 使其失效。确认复用同一 mutation lock，只有 exact 200 `INVALID` response 可采用 baseline；Canvas
   Focus 显示有界 problem code/pointer/count/truncation，并提供具名“仍保存为 INVALID”与取消动作。
