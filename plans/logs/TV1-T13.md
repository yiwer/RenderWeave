## 产品增量

1. `renderweave-asset` 新增 provider-owned `AssetResolver` 与 outbound `AssetFetchEndpoint`。Resolver 输入只含
   request/scope/resource/asset/kind/audience/deadline；precheck 不读 metadata、不 pin current。resolve 生成
   domain-separated 完整 fingerprint，deadline 取绝对 UTC，稳定返回 rejected/conflict/timeout/unavailable。
2. `PostgresAssetPersistence.resolveForRender` 在单事务内按 `(renderRequestId, resourceId)` advisory lock + row
   lock 线性化：已提交同 fingerprint 重放 exact selection/lease；异 fingerprint 冲突；仅 miss 时以 aggregate
   share lock 检查 scope/ACTIVE/kind 并读取不可变 current content。commit 状态不明后的同请求重试仍先查记录。
3. V024 `asset_render_selection` 只保存 request/resource key、opaque fingerprint/lease handle、expiry 和
   AES-GCM nonce/cipher。selection ciphertext 包含 ownerScope/asset/content/kind/audience/descriptor；随机 nonce，
   AAD 绑定 key/fingerprint/lease/lifecycle，record 自动 sweep。URL 与 token 不落库。
4. app 从 256-bit master key按独立 domain 派生 AES/HMAC key；签名 claims 覆盖 request/resource/asset/
   contentVersion/hash/length/audience/expiry。canonical HTTPS bearer path 只供内部 Renderer；endpoint 拒绝
   cookie/range/非 identity compression，验证 token/record 后加载 exact S3 blob，在任何响应字节前校验
   sha256/length，再以固定 1 MiB 块输出精确 body。
5. Rendering-owned `AssetResolutionPort` 由 app anti-corruption Adapter 接入 production Resolver；所有 closed
   outcome 无 default bucket 地映射为 Rendering code。Evaluator 改为每次 evaluation 从注入 Clock 冻结
   `now + 60s`，消除把部署数值 `60000` 当 Unix epoch 的错误。Materializer 保留 nested child 的原始
   Asset-resolution failure，而不再折叠为 generic internal error。
