## 产品增量

1. 新增 Structured-only editor session：E1 baseline canonical bytes、parsed DesignDSL、revision 与 contentHash 作为
   不可变快照保留，working copy/history 与 baseline 分离；baseline、working object 和 history 均以冻结与 defensive
   clone 防止别名修改。同 baseline readiness 更新只替换 authority 状态，新 revision/hash 才重建 session。
2. 首个 closed structural command 为 `set-template-display-name {before, after}`。输入精确复刻 Java
   `String.trim()` 的 `U+0000..U+0020` 端点规则，按 Unicode scalar/code point 校验 1..128，拒绝未配对 surrogate，
   保持 16 MiB canonical 上限；对象成员递归按 UTF-8 bytes 排序，lossless decimal/int64 token 不被 number 化。
3. canonical dirty 的唯一事实为 working 与 baseline compact canonical bytes 是否全等。canonical no-op 与无效输入不
   写 history、不清 redo、不递增 generation；全部 structure/nodes/assets/definitions/exchange/canvas/inspector 投影
   都改读 working copy。
4. history 以 closed command 做结构重放，past 最多 100 条；undo/redo、分支后清 future、最旧项逐出均有回归。
   每次有效 edit/undo/redo 单调递增 `previewGeneration`，使任何旧 future preview result 失效。
5. preview guard 只在 canonical clean 且绑定 current identity 的 fresh readiness 为 `READY` 时 eligible；dirty、
   recheck pending/unavailable/`INVALID` 分别返回 closed blocker。该状态只真实展示资格，不提供 preview action、
   endpoint、结果槽或 synthetic image。
6. Canvas Focus shell 增加工作名称、canonical clean/dirty、44px undo/redo、真实本地名称表单与错误关联、working-copy
   五区投影和克制 live status。dirty 时抑制会替换 baseline 的 E1 reopen，undo 回 clean 后恢复 retry；同 baseline
   pending/invalid/unavailable 更新都保留草稿。Raw Repair/Compatibility 行为不变。
7. 组件仍未挂载 `/templates/:templateId`，也没有 save/conflict/overwrite、dependency confirmation、reconciliation、
   authoritative preview、recovery、import、Asset picker、E9 problem projection 或相应 disabled placeholder。
