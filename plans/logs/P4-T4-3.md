## 关键结果

- OpenAPI 0.7.0 增加 60 个 replay fixture 列表、幂等创建/查询 run、Candidate 查询/保存和 run-bound image artifact；生成的 TypeScript SDK 与服务端合同同步。
- HTTP 创建仅允许 `replay-v1` 合成 fixture，要求 `Idempotency-Key` 和显式 input-scope 确认；profile 显示 `provider=REPLAY`、`networkAllowed=false`，没有真实上传或 live provider 入口。
- 精确 `claim(runId, ...)` 只执行刚创建的目标 run；PostgreSQL 回归证明不会误领另一个 queued run。
- Candidate `original_json` 永久不变，`current_json` 用 candidate revision 乐观更新；run sequence 同步递增并写 `CANDIDATE_UPDATED` event。
- 保存策略先检查 stale revision；AI source、confidence、inferred、evidence 与父 Schema 身份不可改。AI semantic edit 必须进入 `RESOLVED_BY_EDIT`，逻辑移除必须保留 item 并使用 `REMOVED`。
- 单次保存最多改变一个既有 item resolution；API 集成测试明确拒绝 bulk resolution，没有 confirm-all endpoint、状态或 UI 操作。
- REMOVED 字段不再因自己的低置信/未解析类型阻塞，但 active reference 指向 removed Schema 仍产生 missing-target blocker。
- UI 以 run-local `candidateSchemaId` / `candidateFieldId` 维持选择与证据关联；编辑 key 不会改变 evidence identity，也没有把 Candidate ID 引入正式 Schema DSL。
- Schema bundle 导航、Form 和一层 Map 共用一个 reducer；数组元素单独编辑且不提供 `Array<Array<T>>`；引用可选择 Candidate、Draft 或 Static 目标。
- 每次 semantic action 自动串行保存；保存期间继续输入会保留本地新 generation，成功后采用服务端新 revision 再续存。409 保留本地修改并要求显式重载/重试。
- 图片证据使用 0..10000 坐标覆盖归一化 PNG；JSON 证据只显示 sample index 与 pointer，不回显原始值。AI provenance 在检查器只读。
- blocker 全部解除后只显示“审核门通过，T4-4 才开放原子创建”，本节点没有 apply 按钮；真实浏览器旅程和 API 测试均证明 Draft 表保持零写。
