## 实现结果

- Draft 列表、revision history 与 StaticSchema 列表改用轻量 persistence projection；列表路径
  不再读取或反序列化完整 DefinitionDSL、compiled JSON Schema 或 release note。精确详情与
  revision endpoint 仍按原合同加载完整内容，OpenAPI/Web 合同无需变化。
- Draft 详情在 shared advisory lock 下只解析根节点的 reachable closure；写操作继续使用
  exclusive lock，并只检查 proposed targets、reverse ancestors、forward descendants 与 Static
  depth。缺失引用、环和最大深度仍在提交前 fail-closed。
- Replay 与 Live 使用同一个单节点 fair two-lane coordinator。Replay HTTP create/retry 不再绕过
  上限；production scheduler 可回收 `QUEUED` 和 lease-expired Replay/Live run，异常路径归还 permit。
- Hikari 默认池显式设为 16（10 session + 2 workers + 运维余量）；V011 添加 Draft/Static 排序
  索引与按 `networkAllowed` 开头的 partial claim 索引。generic prepared plan 实际选择
  `inference_run_network_claim_idx`。
- `tools/run-gate.ps1 -Gate capacity` 捕获固定数据计数、median/p95/max、PostgreSQL
  `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`、并发不变量和零外部调用证明。

## 决策、偏差与残余

- 没有设定或宣称 latency/throughput SLA；本节点建立可复跑的比较基线和 correctness gate。
- 摘要 SQL 的 `jsonb ->>` / `jsonb_array_length` 仍可能在 PostgreSQL 内部 detoast
  DefinitionDSL；已消除大对象从 JDBC 进入 JVM。若 DB I/O 成为瓶颈，再物化 displayName /
  fieldCount 列，不能把本次修复表述为“数据库完全不读取 definition”。
- Draft contains-search 的本机计划仍扫描 100,000 revision 后与 10,000 current rows 连接；当前
  p95 为 32.311 ms，保留为数据分布增长后的观测点，不在没有证据时引入 `pg_trgm`。
- two-lane 上限是单应用实例约束；未来横向扩容必须引入数据库/分布式全局许可，不能把
  `2 × replicas` 误称为全局 2；本节点也没有证明 shutdown drain。
- 10 条 HTTP journey、2 次 DB claim 与 2 条 coordinator lane 是同一固定基线中的分阶段测量，
  不是“10 + 2”同时压测，不能据此推导组合吞吐。
- 固定夹具覆盖稀疏图和深度 10 链，不是 256 万 edge 的理论最密图；也未提供 JVM peak heap、
  Hikari pending/advisory-wait 的生产遥测。它们是后续生产压测/观测工作，不影响本节点的
  已测信封。
- V011 只新增索引；若需回退，可单独删除五个 V011 index。pool 与 recovery scheduler 均可用
  环境变量回退；projection/coordinator/graph 实现可 revert `d5534de`，无外部费用或数据改写。
- 未修改 Prompt、Profile、corpus、authorization、OpenAPI 或 Web；全部 live gate/ledger 保持关闭。
- 再锚定未发现 Template、Workspace、Renderer 或 AI 权限扩张。
