## 交付

- 新增 image / JSON / combined multipart live API 与 AI 识别 UI；上传只创建 durable `QUEUED` run，不在请求线程触发外部调用。
- live availability 只公开安全的 Profile、模型、价格快照和全局预算状态；服务端同时要求 deployment enabled、Key configured、`SYNTHETIC` 分类、外传确认和实验性 Profile 确认。
- replay 与 live 使用独立 claim 查询；live worker 以租约执行 OBSERVE → STRUCTURE → DETERMINISTIC_VALIDATE → CRITIQUE → bounded REPAIR，并复用既有 Candidate 审核/create-only 原子落库边界。
- 新增 V008 预算与 attempt telemetry：全局最多 6 次、¥1（1,000,000 微元）；每次 provider call 前在 PostgreSQL 行锁内 fail-closed 预留，retry/repair 同样计数，未知或崩溃调用保留预留额。
- provider 原始输出仅在内存中通过 strict Candidate codec；持久层只保存成功解析的 Candidate、确定性问题与 request id/model/token/cost/duration 等有限元数据。
- 缺 Key 不预留预算、不触网并安全失败；retryable provider failure、无效输出 repair、模型不匹配、预算耗尽和 worker recovery 均有稳定状态。
- 审核页可轮询 QUEUED/RUNNING/FAILED，Candidate 就绪后进入原有逐项审核；基础 Compose 默认关闭 live，`compose.live.yaml` 才通过 secret 挂载 Key 并显式开启。

## 安全与恢复

- 本节点的全部自动化验证均显式移除了 `DASHSCOPE_API_KEY` 和 `RENDERWEAVE_RUN_LIVE_CANARY`；没有读取/输出真实 Key、没有发送数据、没有产生费用。
- V008 是兼容式前向迁移：将 provider-neutral 的 source reference 正名，并新增预算/telemetry 表；恢复应用代码可 revert 本节点，数据库采用后续前向迁移，不删除已有记录。
- live 默认关闭；紧急熔断为移除 overlay 或设置 `RENDERWEAVE_LIVE_AI_ENABLED=false`。预算行是第二道不可绕过的持久化硬限制。
- A2 尚未满足；T5-4 canary 只证明真实通路，不能把两条样本结果冒充 T5-3/T5-5 的 60-case 质量认证。
