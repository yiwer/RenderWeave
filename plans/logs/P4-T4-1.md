## 关键结果

- `image-only`、`json-only`、`combined` 强制显式外部传输确认、数量/单项/批量上限与声明 media type；图片只接受 magic 与声明一致的 PNG/JPEG，拒绝 APNG、多帧、超长边和不可解码数据。
- JPEG EXIF orientation 在规范化前应用；图片经显式内存缓存流解码并转成去 metadata 的 sRGB PNG，避免 ImageIO 默认磁盘缓存原始 bytes。
- strict JSON 拒绝重复成员、非 object 根、trailing token 和 depth>32；只保存字段路径/类型等结构摘要，不保存 sample value 或原始正文。
- 相同规范化图片共享 content-addressed artifact，但 `NormalizedInputReference` 保留每个图片 occurrence ordinal，后续 evidence 可稳定引用图片序号。
- 文件适配器用 SHA-256 locator、根目录约束、staging + atomic move、幂等写与读时摘要校验；创建失败只清理由本次新建的规范化产物。
- V005 以 DB check 固化 run state/lease/terminal timestamp 一致性；run、event、input occurrence 与 artifact 分表，未增加 raw input/body/content 列。
- 同一 Idempotency-Key 并发请求由 PostgreSQL transaction advisory lock 串行化：同请求返回同 run，不同 fingerprint 稳定冲突且零额外写。
- `FOR UPDATE SKIP LOCKED` 证明并发 worker 不重复 claim；续租、过期接管与 stage checkpoint 使用 lease token 防止旧 worker 提交。
- queued 取消立即终态；running 取消先置 cooperative flag，再由有效 lease 确认；FAILED/CANCELLED retry 创建新 run、复用规范化 artifact、重置到 NORMALIZE 后的安全起点。
- 永久删除 run 只在最后引用消失时把 artifact 标为 `deletion_pending`；文件删除成功后才确认 DB 删除，存储失败可跨重启继续清理。
