## 决策与合同

1. 作者侧 use cases 由一个 `TemplateApplication` deep Interface 收口；Rendering snapshot/closure 与 Asset 删除
   proof 分别由 `TemplateSnapshotAuthority`/`AssetReferenceAuthority` 拥有，不把 persistence record 当共享 API。
2. Ticket 06 只在真实纵切中物化 create/current-read/save；未来 operation、confirmation、snapshot/reference
   Interface 没有 consumer/behavior 前不创建 unsupported method、空 SPI 或 placeholder outcome。
3. server-only invocation 与用户 command 分离。`OwnerScopeAuthority` 解析 create/existing/recheck，响应按 read
   disclosure 分 readable canonical baseline/opaque commit receipt；跨 scope 和权限组合执行冻结的
   NOT_FOUND/FORBIDDEN folding，请求不能自报 ownerScope/capability/role/Workspace/authorized boolean。
4. `.spi.TemplatePersistence` 只接受 internal 构造的 admitted create/append transaction，隐藏 SQL/JDBC/lock/
   exception；PostgreSQL 与 ordered scripted Adapter 是两个真实实现。它没有 revision update/delete、aggregate
   purge、scope/Schema rebind、generic CRUD/Result/Problem。
5. aggregate 永久拥有 opaque identity、ownerScope、exact StaticSchemaRef；revision 从 0 连续追加完整 JSONB +
   contentHash。trusted read 重新 canonicalize/hash，完整性漂移 fail closed 且不回写。create/save 的授权、
   canonical、Schema/dependency、recheck 与 commit 顺序以及五项 transaction invariant 已精确冻结。
6. INVALID confirmation 只属于未来真实 dependency slice：完整未截断 problems 才能签 token，confirmed request
   重交完整 DesignDSL 并全量重验；create/hard/cycle/security/budget/truncated problems 无 token，永无 force。
7. forward-only persistence 继续服从 ADR-0003：T06 才选择届时下一 migration；既有 migration 不改、无 down、
   普通 PostgreSQL constraints、无 immutability trigger。Ticket 04 的 92 个 atomic requirements 已按区间映射
   到 ADR-0042，不重发或改号。
