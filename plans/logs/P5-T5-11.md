## 结果

- 新 attempt 不再产生合并的 `CANDIDATE_DECODE_VALUE_INVALID`：
  - Candidate 枚举错误使用 `CANDIDATE_DECODE_ENUM_INVALID_*`；
  - record 构造不变量使用 `CANDIDATE_DECODE_CONSTRUCTOR_INVALID_*`；
  - UUID、整数、布尔等非枚举格式错误使用 `CANDIDATE_DECODE_FORMAT_INVALID_*`。
- 槽位只来自封闭常量映射。Provider 值、字段名、动态 map key、数组索引、JSON path、
  Jackson 消息与类型名不会拼入 code；未知位置只进入固定 fallback。
- Candidate strict codec 关闭 scalar coercion、float-to-int 与 enum ordinal 读取，防止非法值
  被静默接受而绕过 taxonomy。
- 对外错误语义保持 `CANDIDATE_JSON_INVALID`；attempt telemetry、PostgreSQL、journal 与 report
  沿用既有 bounded Map 信封，无需 migration 或版本升级。
- 历史 `CANDIDATE_DECODE_VALUE_INVALID` 继续可读取、排序与聚合，不被重写；T5-10 evidence
  与永久 `CLOSED` ledger 均未修改。

## TDD 与回归

- 红测先证明 source enum、其余四种 Candidate enum、record 非空构造、UUID/整数格式与
  numeric-enum/string-scalar coercion 均不能满足目标归因。
- 21 个 Candidate contract tests 覆盖 enum/constructor/format 固定槽位、128 字符稳定 code、
