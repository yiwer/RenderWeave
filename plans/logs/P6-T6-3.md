## T6-3a.2 multipart 网关边界

- 用户上传的 multipart 请求体为 1,309,592 bytes；Nginx 在 Java 之前按默认 1 MiB
  `client_max_body_size` 返回 HTML 413。前端对响应直接调用 `response.json()`，因此二次表现为
  `Unexpected token '<'`。API 日志没有对应请求，排除了 Spring 34 MiB 与领域 10/30 MiB 边界。
- Nginx `/api/` 上限改为 35 MiB，略高于 Spring `max-request-size: 34MB`，使应用保持稳定的
  `INFERENCE_PAYLOAD_TOO_LARGE` 合同；超过网关硬边界时，named error location 也返回
  `application/problem+json`。
- live multipart 客户端改为先读取 text 再有界解析 JSON；HTML/纯文本 413 被转换为可读的
  `StudioRequestError`，不再向用户泄漏 JSON parser TypeError 或网关 HTML。
- clean Web A1：revision `eae3d10`，55/55 tests、typecheck、lint 与 Node 24 production build PASS；
  evidence 为 `.sdlc/evidence/20260810-114334-web/metadata.json`。
- 真实部署探针：`nginx -t` PASS；1.25 MiB 合成 multipart 穿过网关并由 Java 返回 JSON 400；
  36 MiB 合成 multipart 返回 JSON 413 / `INFERENCE_PAYLOAD_TOO_LARGE`。探针前后数据库均为
  5 个 inference run、3 个 reservation，因此新增任务=0、新增 Provider 调用=0。
