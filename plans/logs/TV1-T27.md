## 产品增量

1. Template authoring deep seam 新增显式 `recheckCurrent`：先复用 READ capability 与 current integrity authority，
   再以完整 current-only dependency projection 计算 fresh readiness，通过 revision-guarded persistence 只写同一
   current identity；not found/hidden、deleted、integrity mismatch、dependency/authority/persistence unavailable 与
   漂移耗尽均为 closed outcome。
2. `POST /api/v1/templates/{templateId}/readiness-recheck` 返回检查所绑定的 templateId、revision、contentHash 与
   `READY | INVALID`；最多 3 次 current drift 后返回 conflict。既有 GET 仍无副作用，PostgreSQL API 测试证明旧
   STALE read 不落盘、显式 POST 才对同一 identity 写入 fresh readiness。
3. 审查发现既有 `CanonicalTemplateReadinessAuthority` 虽声称只重试一次，冲突路径实际使用无界递归；新增会在
   第 4 次调用失败的 RED 回归测试后，将其改为同样最多 3 次的显式循环，不再有递归或无界数据库重试。
4. OpenAPI source of truth 从 `0.13.0` 升至 `0.14.0`，增加真实 recheck operation，并把 readable current 的
   readiness 从错误单值修正为领域闭集 `READY | INVALID | STALE`；Web SDK/types/index 均由规范重新生成。
5. Web open boundary 使用 raw response text 与 lossless JSON，保留 int64 revision 和 decimal token；按
   `renderweave-design-content/1\0` 加 canonical DesignDSL UTF-8 重新计算 SHA-256。envelope/canonical/hash 不一致
   fail closed，不能降级为 Raw Repair。
6. canonical GET 后顺序执行显式 recheck；只有 templateId/revision/contentHash 全等的 fresh 结果可替换“权威重检
   中”。identity 漂移触发最多 3 次重开，generation guard + AbortController 丢弃已卸载或切换 Template 的旧结果。
   仅网络错误/503 保留可信 baseline 并标记 unavailable；404/410、其他 HTTP、integrity 与 malformed success
   均失败或传播，不伪装为可重试的 authority outage。
7. 新增 Structured / Raw Repair / Compatibility Read-only 三个互斥 session model。Structured 对 exact supported
   profiles 形成只读 preorder；Compatibility 不解析未知 profile；Raw Repair 只承载未来 import raw buffer，不接纳
   损坏的 server current。
8. 按锁定 `design.md` 形成未发布 Canvas Focus shell：56px chrome、五入口左 rail、居中非权威 canvas、右 inspector、
   bottom dock、identity/readiness/revision 状态；导航、节点选择、面板开合与 retry 均有真实行为。skip link、landmark、
   visible focus、polite live status、reduced motion 与 `<1024px` 不支持说明均落地；不存在 save/preview/import/
   recovery 的 disabled placeholder，也未接入 `/templates/:templateId` 产品 route。
