## 关键结果

- `CandidateMaterializer` 只消费已审核 active graph；按 child-first 拓扑顺序输出 strict DSL，丢弃 removed item、Candidate UUID、confidence、evidence 和 provenance。
- Candidate reference 缩窄为 Draft `SchemaRef`，显式 Draft/Static reference 保留精确目标；未解析/冲突类型、嵌套数组、孤立 Schema、环或非法约束在进入 repository 前阻断。
- materializer 还会通过权威 strict parser/writer 往返一次，Draft JSON 没有 Candidate-only 字段，正式 Schema 身份仍为 `SchemaKey + fieldKey`，没有引入 `fieldId`。
- inference 模块只暴露一个 `CandidateApplyStore.apply` capability；architecture test 保证 application port/service 没有 publish、update、delete、SQL、filesystem 或 HTTP escape hatch。
- V007 为 Candidate 增加成对的 `final_json/applied_at`、不变式和 2 MiB 上限。apply 成功后 final 只读；重放同一 revision 返回同一完成结果。
- `REVIEW_REQUIRED → APPLYING → COMPLETED`、final snapshot、全部 AI Draft revision 0、reference edges 与两个 event 在一个 PostgreSQL 事务中完成；StaticSchema 无写入路径。
- tombstoned/active key 冲突、root 插入故障和两个 run 并发争用同键的 Testcontainers 测试分别证明：失败 run 保持 review + artifacts，无部分 Draft/revision/edge/final/event；并发仅一个胜者。
- applying 原子段明确拒绝 cancel；queued/review cancel、cooperative running cancel 与 manual retry 创建新 `retryOfRunId` run 继续使用 durable input，不复制 raw data。
- SSE 使用持久化单调 sequence，支持 `Last-Event-ID`/查询 cursor 和至少一次语义；客户端只去重并 refetch TanStack Query 权威快照，mutation 不自动 retry。
- OpenAPI 0.8.0 新增 apply/cancel/retry/events 合同和 final Candidate；生成 SDK 与手写 SSE client 已同步。
- UI 只在 blocker=0 且 autosave 稳定时开放原子创建；Radix 确认窗明示键集、revision 0、冲突整包零写与不发布/覆盖保证。完成后编辑器冻结并提供 Draft Studio 链接。
- 真实浏览器旅程使用 `combined-17-all-null` 解决 blocker，验证 Candidate `COMPLETED/ATOMIC_CREATE`、final 存在、AI Draft r0 可读、StaticSchema total 前后不变，并实际进入新 Draft Studio。
