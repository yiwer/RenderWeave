# 收口 Template v1 的安全、容量与验收合同

Type: grilling
Status: open
Blocked by: 05, 14, 15, 16, 18

## Question

在所有语义决策完成后，Template、Asset、Evaluator、RenderDocument 与 RenderEngine 的权限矩阵、能力否定清单、大小/深度/循环/资源/延迟预算、并发和失败边界是什么；哪些可执行场景与证据等级足以让最终规格进入实施规划？

## Inherited constraints

- Template mutation 只有 best-effort 服务端防抖，没有 command-key 幂等；验收必须覆盖超时重试可能重复创建/复制以及客户端协调责任。
- current report 不绑定 revision，旧异步结果允许覆盖；验收必须证明编辑器打开和每次 Render 的权威重检能阻止 INVALID 内容产生 RenderOutput。
- Template 本地 revision/current/dependency projections/readiness/report 必须原子；Template closure snapshot 不允许混合并发 current。
- DELETED 是保留历史但不可恢复的终态；incoming ACTIVE TemplateRef 阻止删除，TemplateRef graph 必须是 DAG。
- Asset 的 ownerScope/kind/identity 不可变，能力面为 asset.read/create/update/delete/restore；直接跨 scope/不可读查询隐藏为 NOT_FOUND，Rendering 使用内部同 scope Resolver。
- exact `renderweave-asset-acceptance/1.0` 固定 IMAGE 64 MiB/20,000 px edge/100M pixels 与 FONT 32 MiB，并要求真实字节完整解析；验收必须证明 Renderer profile 是其兼容超集。
- Asset 不设 scope 配额且 v1 不 GC；部署必须有新 Blob fail-closed 容量 breaker。创建幂等结果保留 24 小时，删除确认 token 为 5 分钟单次并绑定完整引用 proof。
- AssetRef按实际Node property消费位置独立解析，允许一次Evaluation混用同一Asset的不同contentVersion；每个occurrence一对一形成ResolvedAsset与RenderResource。验收必须同时证明单项exact、晚到失败零输出、manifest引用集合精确相等及resourceId不碰撞。
- RenderInput 的字节、深度、customValues 条目数和 strict-JSON 结构预算必须在 last-wins 分组和 ignored-target 消解前施加；duplicate loser、unknown/PRIVATE winner 虽不做声明类型校验，也不能绕过全局 admission 预算。
- 验收必须证明 RootDocument 每次按 TemplateSnapshot 精确 StaticSchema 验证、未知字段对 Evaluator 不可见、optional missing 为 typed ABSENT、有效 PUBLIC winner 类型错误使整个请求零 Evaluation/零输出。
- 验收必须覆盖 customValues omitted、duplicate last-wins、loser 不做值级校验、unknown/PRIVATE 静默忽略，以及 authored child fill missing/PRIVATE 使父 Template INVALID 的非对称合同。
- 原始 RootDocument、完整 customValues、AdmittedRenderInput 与 frame 不得进入普通日志或审计转储；problem collection 必须有上限且不能回显完整敏感输入。
- 必须冻结并验证 DesignDSL/Expression source 字节、Definition/Binding/input/case 数量、graph/dependency chain、AST node、decimal precision/scale、list length、nested target 与 runtime operation/call budgets；限制在解析、presence analysis 与 lazy execution前的适当边界 fail-closed。
- conformance corpus 必须覆盖 Java authority 与 Web feedback 对 type/presence、BigDecimal、Unicode text/blank/safe-regex、lazy branch、Mapping first-match、formatDecimal、source span 和 error code 的一致性；第三方 expression library 不能成为验收语义来源。
- 安全验收必须证明 Expression 无任意 member/index/eval/IO，Capability 只能作为显式 Expression input，Binding/Mapping/Custom/fill 不能直接调用 capability，未知 RootDocument 字段也不能经任意 JSON path 泄漏。
- BindingPolicyCatalog 的新增必须保证 key/target set 不重叠且已有 Policy 字段不可变；服务端不能信任 Template 自报 bindability/type，前端限制也不能替代保存与 Evaluation 权威校验。
- 验收必须覆盖 node-local nested target 的存在性/越界/重复/祖先重叠、静态 baseline 依赖索引，以及 Binding ABSENT/ERROR/type/propertyValidation failure 零 RenderDocument且绝不回退 baseline。
- DesignDSL parser 硬上限已冻结为 decompressed raw/canonical 16 MiB、depth 64、object members 1,024、array items 100,000、total values 1,000,000、string 1 MiB、member name/number token 256 bytes；验收必须证明这些限制在完整 model、decimal expansion、canonicalization 与 dependency IO 前 fail closed。
- 必须为 `renderweave-design-c14n/1.0` 与 domain-separated SHA-256 建独立 conformance corpus，覆盖 UTF-8 member ordering/escaping、Unicode、equivalent decimal/-0、semantic vs set-like arrays、metadata trim、exact Expression source、cross-Template same-content hash 与 trusted-read mismatch。
- 必须证明 unknown member/kind/null/duplicate/unsupported pair 不能被 Web partial model、数据库 JSON serializer、generic JSON mapper 或 migration 绕过；每个 admitted dslVersion/expressionProfile pair 的永久 parser/validator/evaluator compatibility 进入发布验收。
- contentHash 不是签名、authorization、provenance 或 Render cache identity；验收必须覆盖 Asset/Template current 与 BindingPolicy drift 不改 authored hash，同时 closure/input/capability/asset occurrence 进入完整 Evaluation identity。
- Evaluation identity语料必须分别验证renderRequestId、pre-execution evaluationFingerprint、success-only evaluationResultDigest、full-lease renderDocumentDigest与Design contentHash不可互换。closureDigest使用排序unique snapshot与全部authored edge，admittedInputDigest只含closed typed可观察视图；result digest组合capabilityResultDigest/assetSelectionDigest且排除subject、budget、lease与output参数。
- 权威流水线验收必须固定`request admission → closure freeze/recheck → typed input → authored/dynamic Asset admission → CapabilityState → serial lazy materialization/actual resolve → atomic seal → Engine`全序；阶段前错误不能触发后续Clock/entropy/Resolver。closure任一current漂移必须整轮重试，耗尽返回`TEMPLATE_CLOSURE_UNSTABLE`，不得局部补读或混合snapshot。
- parser failure 单问题停止、semantic 有界稳定收集、external dependency 延后、canonical pointer + stable entity target、`PROBLEM_LIMIT_REACHED` 与 sensitive-content redaction 都必须有 executable acceptance evidence；具体更低语义计数和 problem cap 由本票据冻结。
- migration 必须 pure/bounded、exact source/target/hash、preview-first、no implicit save/read-time upgrade；需要新 local identity 时只能使用 client-provided UUID v4 或 manual action，不能让普通 save 生成。
- Node 验收必须证明 Web、save validator、Evaluator/lowering 共享 exact NodeContractCatalog 语义，且 Slot、通用 properties bag、unknown/null、非法 ContentModel/placement、duplicate whole-tree nodeId 与环境字体 fallback 均 fail closed；不得以多份 hand-written switch 的同名测试冒充单一权威。
- BindingPolicy 验收须覆盖首批逐 kind/path expanded Catalog、`[*]` policy 对具体 index、optional baseline 未 materialize、union discriminator/array整体拒绝、append-only non-overlap，以及 overlay 后 leaf + aggregate validation failure 零 RenderDocument。
- geometry/render acceptance 必须覆盖 mm/pt 精确换算、Render Request 省略 DPI 时 96、Canvas/bleed rounding、Image aspect-only HUG、Text explicit FONT/missing glyph、Vector bounds 与 QR square；平台或浏览器默认 DPI/font 不得影响权威输出。
- Layout acceptance 必须为 `renderweave-layout/1.0` 建独立 corpus，覆盖 materialization/gap、FIXED/HUG/FILL 与 cycle、Stack weighted water filling、Grid AUTO/FRACTION/span、constraint-sensitive Text shaping/vertical/BiDi/shrink/ellipsis、Image/Vector bounds、transform、opacity、clip、paint order、stable errors 与 Profile tolerance；浏览器反馈不得作为权威证据。
- 本票据必须冻结 materialized node/occurrence、tree depth、Grid tracks/span constraints、Stack FILL children、Text scalar/grapheme/glyph/line、vector command、measure/remeasure、paint item、clip depth、LayoutTrace item/bytes 与总 layout operation预算。Stack 水位最多 `fillChildCount+1` 轮、Grid span 单调单次处理、Text shrink 固定 32 次；任何预算超限都 fail closed，不近似、不截断 Scene、不返回 partial output。
- 验收必须证明 `render:false` 不解析 dynamic Asset，`visible:false`/`opacity:0` 仍解析实际资源并保留失败；全链路拒绝未知 Layout Profile、non-finite/overflow、fast-math 漂移、环境字体/hinting/DPI layout feedback 与 Engine silent fallback。LayoutTrace 必须受独立授权、redaction 与容量上限约束，且不能进入 revision/hash/cache identity。
- Repeat/Conditional conformance corpus 必须覆盖 exact structural wire、typed items/condition、两种 absent policy、原输入顺序/重复/空集、scalar `system-basic-*@v1` 与 reference item context、祖先loopId词法可达和sibling/descendant越界拒绝。
- 结构惰性验收必须证明固定consumer order、false/zero早剪枝不执行后续Binding/TemplateUse/Asset/capability、visible/opacity仍完整执行、第一demanded error fail-fast，以及item subtree全剪枝后的packing紧凑但loopIndex不重编号。
- 容量合同必须分别冻结collection length、Repeat nesting depth、创建frame/occurrence、materialized node、generated track/cell与总operation预算；每个输入item即使最终被剪枝也消耗collection/frame/operation预算，只有surviving内容消耗materialized/layout/paint预算，超限一律零RenderDocument且不截断。
- Layout/lowering corpus 必须覆盖PACK的FIXED/HUG限制、itemLayout/instanceLayout STACK与GRID、零尺寸materialized项的gap/cell、零survivor移除、true Conditional空Frame、显式AUTO track/cell lowering，以及RenderDocument中不存在Repeat/Conditional/PACK/ValueSource/Loop frame。
- Occurrence与Template composition验收必须覆盖重复item值仍产生不同path、array reorder改变inputIndex path、nested Repeat+TemplateUse segment顺序及合成role无UUID；最终tree先序必须产生连续`rwocc_`+16位lowercase hex ordinal。RenderDocument/Engine只见opaque occurrenceId，完整OccurrencePath/sourceNodeId只在有界请求sidecar并经权限投影，且不进入DesignDSL/RenderDocument/contentHash/revision/cache identity。
- TemplateUse conformance必须覆盖exact structural wire、nodeId/useId uniqueness、无children/appearance、四种parent placement、PACK无FILL、HUG child trim、common/placement-only BindingPolicy，以及templateRef/contextSelector/absentPolicy/fills不可Binding。
- 系统StaticSchema语料必须证明`system-empty@v1`与五种`system-basic-*@v1`是一等不可变StaticSchema；scalar frame精确产生`index/value`，`/index == loopIndex`且保持原输入index，reference item不注入index，system-basic context可调用匹配Schema的child。
- Context/fill语料必须覆盖invocation/loop/empty selector、空pointer whole-context、reference subtree、exact Schema equality、ERROR/SKIP、PUBLIC/default/PRIVATE、ABSENT default、canonical targetDefinitionId order、duplicate target hard error，以及child current definition漂移使父STALE/INVALID。
- Closure验收必须覆盖全部authored edge（含静态不可达branch）、same-scope、snapshot按templateId去重、diamond shared snapshot/independent invocation、current漂移重试或失败、save+DAG原子性、incoming delete blocker及child变化不改父revision/hash。
- compositionViewport Layout corpus必须覆盖source trim原约束layout、concrete background、bleed忽略、source+host clip、CONTAIN/CENTER、透明letterbox、HUG min/max、FIXED/FILL、全subtree geometry/font/stroke缩放、nested viewport与parent sibling连续paint order；RenderDocument/Engine必须拒绝TemplateUse/child Canvas/callback残留。
- Profile验收必须证明root DesignDSL Profile唯一选择exact Layout Profile、每个child存在永久无损lowering edge、caller不能协商/latest、subtree不能混用Profile、缺失edge整请求零RenderDocument。
- RenderDSL验收必须证明`renderweave-render-command/1.0`、`renderweave-render/1.0`、`renderweave-render-c14n/1.0`与`renderweave-layout/1.0`独立exact，不能复用旧Haibo version。closed top-level、static kind union、RenderNodeContractCatalog lowering、default展开、PACK/dynamic structure零残留与六位HALF_EVEN canonical number必须由Java/Rust同一corpus独立重放。
- Seal语料必须覆盖唯一Canvas、opaque ordinal、strict tree/manifest一对一双射、动态/业务身份零残留、空Canvas成功、canonical byte/digest vectors及malformed sealed document折叠`RENDER_INTERNAL_ERROR`。任何partial builder/document/sidecar不得发送、公开、持久化或用于断点续跑。
- Ticket19必须分别冻结unique closure snapshot、authored edge、closure depth、actual invocation occurrence/depth、compositionViewport、expanded node/paint item预算。skipped use只消耗closure预算，shared snapshot计一次而实际invocation逐次计数，任一超限不截断/共享结果/返回partial output。
- 嵌套授权与诊断必须证明Template immutable ownerScope、same-scope ref/copy、内部child/Asset resolution不依赖逐项caller read、cross-scope隐藏且不可确认保存；problem仅暴露有界parent use/child occurrence identity并redact context、fill、完整child DSL/文本/Asset bytes。
- AssetRef wire验收必须覆盖服务端生成canonical lowercase UUID v4、closed `{assetId}`、expected kind由ValueType派生，以及null/unknown member/non-v4/URL/hash/contentVersion/data URI fail closed；`list<imageRef/fontRef>`逐atom提取，但Repeat继续拒绝这两类list。
- closure admission语料必须覆盖每个unique TemplateSnapshot的全部authored Asset atom：static baseline、Custom default、Definition literal、Mapping case/default、asset-ref list、Binding覆盖、未选择branch与静态不可达child；重复assetId保留occurrence，shared snapshot只检查一次，检查只含same-scope/existence/ACTIVE/kind且不冻结current。
- 外部PUBLIC override语料必须证明每个asset atom在使用前统一检查same-scope/ACTIVE/kind/caller `asset.read`，不可见与跨scope折叠NOT_FOUND；AdmittedAssetValue可跨definition/binding/fill传递，但每个最终消费者仍独立resolve。authored同scopeAsset不要求render caller逐项asset.read。
- runtime顺序与并发语料必须冻结materialized authored DFS、NodeContract property声明与Run index顺序，在concrete property/aggregate validation后串行resolve并first-demanded-error停止。必须覆盖两个occurrence之间replace、resolve后delete、同assetId混合contentVersion、最后resolve后变化不影响输出，以及`render:false`剪枝和`visible:false/opacity:0`仍失败。
- Resolver协议验收必须覆盖最小输入、`(renderRequestId,resourceId)`同fingerprint幂等重放、不同fingerprint冲突、提交状态不明先查记录、pre-commit retry可见新current与post-commit绝不重选；短期加密记录和Renderer-only lease须绑定exact request/resource/audience/content/hash/length/expiry并覆盖deadline余量。
- RenderResource验收必须覆盖closed字段、encounter order、一occurrence一entry、tree引用集合相等、unused/missing/duplicate/colliding resource hard failure，以及`rwres_`加64位lowercase SHA-256的versioned canonical locator算法。Engine不得接收assetId/contentVersion/ownerScope/Template identity，含lease的RenderDocument不得公开、持久化或跨请求复用。
- RenderDocument transport验收必须证明digest覆盖完整canonical bytes及fetchUrl/expiresAt、Engine核验后才执行、同一活跃request重建byte-identical。unknown-outcome仅可在原deadline/lease内重发相同requestId/bytes/digest；新请求或任一字段漂移不得续签、重seal、重新resolve或借旧document恢复。
- fetch安全语料必须证明HTTPS exact origin/path-prefix allowlist、空生产allowlist失败、无redirect/proxy/cookie/caller header/range/transparent compression/fallback；仅transport/5xx可在原URL/expiry/deadline内有界重试，4xx/expiry/integrity/profile失败不得续签、重选current或换URL。
- 字节与descriptor语料必须覆盖length/hash/media/magic/完整decode，IMAGE八种orientation、encoded/logical dimensions、`frameCount=1`与`colorEncoding=SRGB_8BIT`，FONT `faceIndex=0`、`TRUETYPE_GLYF|CFF`和unitsPerEm；stored descriptor与exact bytes任何不一致零输出。图片DPI、系统/内置/family字体fallback、自动转码与缺glyph替代必须不可观察。
- cache验收必须证明logical current/Resolver result不共享缓存；verified raw bytes仅在可信ownerScope partition内按scope/kind/hash/length/media复用，decoded cache再含exact Renderer Profile，无可信partition时仅请求内。cache hit不减少occurrence/budget/order/lease检查，corruption驱逐并失败且不得回退或重选。
- 诊断与身份验收必须覆盖Template dependency、Expression/Capability、Resolver及Engine layout/resource的具体稳定code和固定stage；只有内部完整性/Profile/lowering违约对外折叠`RENDER_INTERNAL_ERROR`。Engine只返回occurrenceId/resourceId与安全参数，Rendering经请求sidecar按OccurrencePath/ConsumerPropertyRef和Template/Asset read权限脱敏；任何problem/log/trace不得出现URL/token/hash/contentVersion/blob/sourceFileName/bytes/raw network error。
- Asset容量合同必须分别冻结authored dependency occurrence、unique logical asset、actual resolve occurrence、RenderResource entry、unique exact content、按occurrence与unique content的声明字节、图片像素、字体字节/表解析、manifest/URL字节、fetch次数/重试/总deadline；cache不得降低occurrence预算，任一超限零RenderDocument或零RenderOutput且不截断。
- Capability容量合同必须冻结完整closure静态capability source数量、CapabilityState record/position canonical bytes、`totalCapabilityDemands/clockDemands/randomDemands`、HMAC rejection attempts、state初始化重试、fixed expiry/Render deadline余量、result-digest streaming bytes与聚合诊断上限。首次demand在返回结果前预留total+kind单位；memo/cache/物理复用不能降低逻辑预算，超限零RenderDocument。
- Profile/deployment验收必须证明`renderweave-expression/1.0`永久映射`renderweave-capability-clock/1.0`与`renderweave-capability-random/1.0`，部署只有完整支持exact Profile才能admit请求；瞬时Clock/entropy/state-store故障只返回稳定请求错误，不建立dependency projection、STALE/INVALID或revision。无Random source的完整closure不读取entropy，无任何source时不创建CapabilityState。
- CapabilityState并发语料必须覆盖服务端创建renderRequestId、全部准入后/root frame前线性化、同key同fingerprint重放、不同fingerprint冲突、pre-commit有界重试、unknown commit先查记录、post-commit绝不重取样、固定expiry不续期及不同request相同fingerprint仍新建。fingerprint至少绑定scope/authorization、closure、AdmittedRenderInput、exact contracts与effective budgets且不泄漏原始输入。
- Clock corpus必须覆盖UTC午夜、向过去截秒、`0001-01-01…9999-12-31`、不接受leap second/out-of-range、date/time共享snapshot、不同alias分别计数，以及Expression Clock与deadline/expiry单调操作时钟隔离；禁止system/browser/tenant timezone、datetime/epoch/locale与caller override。
- Random corpus必须使用fixed 256-bit nonce验证`renderweave-capability-call-position/1.0`canonical bytes、HMAC-SHA-256 domain/counter、unsigned大端解释、`M=10^18` rejection sampling、零/最大值与128次防御边界。必须覆盖alias重读、不同alias、invocation/loop declaration frame、duplicate/reordered item、nested use/revision及多contract domain separation，不能用统计测试替代exact vectors。
- Capability顺序/惰性语料必须覆盖未materialize Definition和未选择branch零demand、静态不可达source仍触发相应state组件、既有consumer/argument顺序、Definition memo、first-demanded-error停止后续Capability/Asset，以及Capability ERROR不能变ABSENT/coalesce/fallback。三个exact demand上限数值必须与frame/Repeat/operation总预算共同证明。
- Capability identity/cache验收必须证明只有成功Evaluation按demand encounter order形成typed capabilityResultDigest；失败不保存partial digest/transcript。contentHash、声明contract或CapabilityState不能提前命中旧结果，只有pre-execution identity、capabilityResultDigest、assetSelectionDigest及其余完整identity形成后才允许exact downstream cache；不同renderRequestId不共享state或replay语义。
- Capability security/diagnostic验收必须拒绝unknown/member/null/args/version及非Expression-input位置，证明caller不能注入time/seed/nonce/raw state key且RenderDocument/Engine无能力残留。普通log/trace/metrics/公共problem不得输出result、snapshot、nonce、fingerprint、definition/child高基数path或provider raw error；授权结构化problem只能给出有界逐段授权的definitionId/alias/InvocationPath。
- Capability原型/验收不得提供preview pin、production test override或安全随机用途。fixed Clock/nonce只允许内部conformance seam；每次新Authoritative Preview建立新state，浏览器模拟必须非权威。未来任意新能力必须经新exact Expression Profile、closed typed/只读/无业务副作用合同与显式migration，禁止通用tool/plugin及任意网络/付费/mutation包装。
- Evaluator/RenderDocument容量数值必须覆盖Ticket15冻结的closure、admission、runtime、resource、document与diagnostic全部维度，并采用allocation/call前原子预留。同一logical位置不重复语义计数，重试另耗attempt/physical-operation/deadline且不重置；任何超限不截断、不跳项、不近似，零RenderDocument/Output。
- Renderer输出验收必须证明每条Command恰好对应一个根Canvas与一张完整PNG/JPEG；surface只由trim+四边bleed与integer DPI决定，按任意精度公式整体`ROUND_HALF_UP`，省略DPI展开96且layout零pixel snap。票据19必须填写最大DPI、edge pixels、total pixels、decoded working bytes、surface bytes、encoded bytes及allocation-before-limit的exact数值，不能直接把旧busbox的20,000px/150M/256MiB当成已证明答案。
- 必须为`renderweave-render-command-c14n/1.0`、`renderweave-renderer/1.0`、`renderweave-output-png/1.0`、`renderweave-output-jpeg/1.0`、cancel/problem/result与`renderweave-layout-trace/1.0`建立strict wire、canonical/digest和cross-language vectors；同requestId join/replay/conflict、pre-command tombstone、queue-full reservation、shard state loss、deadline不延长及cancel/seal竞态必须用故障注入证明。
- Renderer容量数值还必须覆盖FIFO queue/slot、总deadline与各cooperative checkpoint latency、request registry/temp retention、resource attempt/backoff/fetch bytes/URL与manifest、request-local raw/decode cache、font table/glyph/shaping、paint/clip/chunk、QR/Barcode内容与module、PNG/JPEG encoder工作集、LayoutTrace item/bytes及multipart总bytes。超限只能返回已冻结stable code并零输出。
- fetch安全验收必须覆盖canonical HTTPS、segment-boundary allowlist、DNS/egress每次connect复核、无redirect/proxy/cookie/range/compression/caller header、唯一匹配`Content-Length`、5xx/transport固定无jitter重试，以及4xx/expiry/integrity/decode零重试。每个lease在Command admission须覆盖deadline加Profile safety margin；具体margin、attempt与backoff数值由本票据冻结。
- IMAGE corpus必须覆盖票据05/16限定的PNG/JPEG/WebP子集、唯一EXIF orientation、`SRGB_8BIT`/canonical ICC、straight RGBA8 normalization、premultiplication/source-over/transparent RGB和nearest/bilinear vectors，并证明CMYK/YCCK/HDR/wide-gamut/animation/16-bit等拒绝。FONT corpus必须覆盖single-face monochrome `glyf`/CFF、允许layout tables、全部被拒字体特性、missing glyph与decoration metrics错误。
- exact像素与编码验收必须冻结CPU target、grayscale AA、coverage/blend、sampling、PNG chunk/filter/zlib/pHYs及JPEG JFIF/ICC/table/4:4:4/quality；每个READY OS/CPU/SIMD组合独立重放。Layout tolerance通过不能替代pixel exact，pixel exact不能替代encoded byte exact，任何旧Haibo测试或浏览器截图都不能单独满足证据。
- QR/Barcode corpus必须覆盖祖先与compositionViewport累计transform、允许positive uniform rotation及拒绝reflection/skew/nonuniform、整数module pitch与小于1px失败；QR覆盖UTF-8 byte+ECI26/version/mask/quiet zone，EAN/UPC覆盖check digit与各quiet zone，Code128覆盖B/C最短方案/tie/checksum，并以matrix与独立decode双重验证。
- 输出transport验收必须覆盖raw image headers、Content-Digest、closed result、JPEG quality、完全编码后atomic seal、post-seal传输越过deadline、截断后exact replay，以及trace multipart固定两part/双digest/顺序与任何校验失败零public release。trace over-budget必须失败而非截断，普通合法overflow只可成为授权trace flag而非warning。
- Renderer Profile的语义per-request上限必须是READY部署能完整兑现的最低保证；deployment concurrency/queue只能在accept前BUSY，不得给已接受请求套用更低隐藏上限。Profile certification必须绑定机器manifest、reference commit与golden corpus，任何Layout/Renderer/Output/Acceptance/wire可观察变化按票据16的所有权规则发布新exact版本。

## Decisions so far

### 1. 宿主权限与诊断投影

- v1只定义ownerScope宿主映射的原子能力，不定义角色、成员、Workspace、共享关系或逐Template/逐Asset ACL。Template能力集合精确为`template.read/create/update/delete/render`；Asset能力集合保持`asset.read/create/update/delete/restore`；布局诊断另设`render.trace`。这些名字是授权输入，不进入DesignDSL、RenderInput、RenderDocument或Engine Command。
- Template目录、详情、历史、export及已删除历史读取要求`template.read`；创建要求`template.create`；保存、invalid-confirmation save、revision restore及冲突覆盖要求`template.update`；删除要求`template.delete`；Render要求`template.render`。同scope copy同时要求来源`template.read`与目标scope的`template.create`。
- Authoritative Preview要求`template.read + template.render`；Save-and-preview还因前置save要求`template.update`。只有`template.render`的调用者可以取得成功RenderOutput，但不能据此看到DesignDSL、revision历史、child Template或Asset明细。
- LayoutTrace请求要求`template.render + render.trace`；只有对相应Template拥有`template.read`的segment才能由sidecar投影为作者定位，其余segment删除或脱敏。`render.trace`不授予Template/Asset读取、Render、编辑或任意Engine访问能力。
- Asset直接目录、详情、版本、download及草稿资源选择要求`asset.read`；create、metadata/content update、delete与lifecycle restore分别要求同名能力。外部PUBLIC override中的AssetRef在admission要求`asset.read`；已获准Render根Template后的authored same-scope Template/Asset解析使用内部能力，不逐项继承调用者read权限。
- 各Host capability互不蕴含。按ID访问跨scope目标，或调用者既无目标操作能力也无对应`read`时，统一返回namespaced`NOT_FOUND`；调用者已有对应`read`、但缺少目标mutation/render/trace能力时返回namespaced`FORBIDDEN`。具备目标操作能力但不具备`read`仍可执行该已授权动作，但响应、问题和sidecar投影必须删除作者内容、revision/child/Asset明细及其他只读事实。
- authorization在confirmation、queue admission或执行前漂移时，尚未发生的操作零写/零输出并按最新事实返回；已原子完成的Template/Asset mutation不回滚，结果不明进入既定reconciliation。Render/trace在atomic output seal前权限失效必须丢弃全部结果，seal后的transport只重放该已授权sealed response，不重新扩展诊断。

### 2. 单一容量合同与工作负载边界

- v1只有一套不可由调用方协商或选择的容量合同；不提供small/large、preview/production或interactive/batch等级。每个限制归属拥有相应语义的exact wire/Profile，所有有效预算进入Evaluation fingerprint；不存在独立的`latest`容量配置或请求级降档。
- Renderer Profile中的per-request语义上限是READY部署对已接纳请求必须完整兑现的最低保证。部署queue、slot及资源水位只允许在接纳前原子返回`BUSY`，不得在接纳后施加更低隐藏上限、排队续期deadline或改用近似路径。
- 合同工作负载固定为一个根Template closure、一个根Canvas和一张完整PNG或JPEG，服务于在线编辑器的Authoritative Preview与单图Render。batch、多页、超大海报、多输出及后台持久job不进入v1容量目标。
- 请求hard deadline及各阶段checkpoint属于正确性和资源安全合同；p50/p95、吞吐率与排队等待等运营SLO不进入语义Profile，也不能改变相同输入的结果或错误边界。
- v1 reference deployment固定为每Engine实例`4 vCPU / 8 GiB RAM / 4 GiB ephemeral`、`1`个active slot与`4`个FIFO queue positions；扩容使用更多相同认证实例，不在同一实例临时增加并发。其他部署可以配置更多资源，但若改变OS/CPU/SIMD、执行路径或无法完整预留每slot合同工作集，就不是同一READY target。

### 3. 唯一v1 READY平台

- v1只认证`Linux x86_64-v2`、CPU-only、固定软件raster/codec与固定SIMD路径的权威Renderer target；禁止GPU、fast-math、环境字体、运行时算法/ISA分派或未认证fallback。具体机器、OS image、dependency及构建事实由只读machine manifest钉死。
- Windows、浏览器Canvas及其他OS/CPU/SIMD组合只可用于开发反馈，在各自独立完成全部exact corpus认证前不得宣称READY、不得成为权威Preview/Render路径，也不得贡献跨target的“多数一致”结果。

### 4. 规划入口与实现验收分层

- 最终规格进入实施规划的门槛是：全部数值、stable code、阶段、场景oracle和所属exact contract均已冻结；机器可读场景清单、向量格式、预算矩阵及需求追踪在固定revision上通过A1工具捕获验证；所有issue清零。该门槛不循环要求尚未实现的产品先通过conformance。
- 实现成为READY的门槛另行要求：Java authority与独立TypeScript反馈实现重放Design/Input/Expression语料，Java与Rust重放各自接缝上的canonical wire/digest/RenderDocument admission语料，Rust Renderer在每个获准target执行完整pixel/encoded-byte golden并由独立runner重新执行和核验，形成A2；故障注入、安全和layout证据同样按场景职责覆盖，不要求无关语言重复全部语料。发布流水线以A3 CI/分支策略固定target、manifest、case清单、revision与artifact hash并强制不可跳过的Profile corpus。当前仓库没有A3，因此不据本地绿色gate宣称发布就绪。
- Editor可访问性、键盘流、焦点恢复及体验验收保留J1；A1/A2/A3自动证据只能报告`automated_verified`，不能替代人工`accepted`。浏览器截图、旧Haibo单侧测试或自报结果均不能单独提升证据等级。

### 5. 数值校准方法

- Ticket19的未冻结数值须先经一次隔离的非产品容量校准：只在`.scratch`记录负载模型、生成协议、固定target machine manifest、测量原始结果、峰值资源与推导余量，不修改产品模块或建立占位runtime/API。
- 校准覆盖每个限制的边界下/边界值/边界上、组合最坏路径、allocation/call前预留、取消/deadline/fault injection及零partial output。最终数值必须同时有静态上界推导和目标机器测量支撑；单次平均值、浏览器表现或无原始证据的经验数不能成为合同。
- 旧busbox实现与测试只作为候选场景、算法和风险线索；其`20,000px/150M/256MiB`等数值、并发fetch、环境fallback及缺失的cancel/registry/descriptor/trace边界不得直接继承为RenderWeave v1答案。
- 当前环境、既有gate/corpus模式与不可转移证据的只读盘点记录在[`capacity-calibration.md`](../capacity-calibration.md)。截至2026-08-15，已在现有Docker Desktop Linux Engine中使用pinned Rust image、4 vCPU/8 GiB cgroup与x86-64-v2编译路径完成非产品A1虚拟化harness；原始结果保存在`.scratch`。旧busbox源码/benchmark仍不可访问，仓库仍没有真实Template/Renderer conformance实现。
- 该A1虚拟化校准与静态公式只支撑本票据的规划数值选择，因此数值可标为planning-frozen；它不证明真实layout/shaping/raster/codec/fetch/cancel路径，也不能替代未来物理Linux target上的A2独立重放和A3 READY gate。harness与fixture继续只允许位于`.scratch`，不得演变为产品Renderer占位实现。
- DesignDSL、RenderInput、closure、Repeat、Node和problem的离散结构上限由产品工作负载与组合复杂度先行选择，再以fixture验证；surface、decoded/encoded working bytes、font/layout/fetch、deadline与checkpoint数值必须同时具有静态上界公式和pinned Linux测量。每个限制至少包含`limit-1/limit/limit+1`及一个组合最坏路径；queue/slot仍是部署接纳合同而非调用方Profile选项。

### 6. Closed-world能力否定清单

- v1可观察能力面只包括已列出的Host capability、`renderweave-expression/1.0`永久拥有的Clock/Random closed operations、Rendering内部AssetResolver及RenderEngine按exact fetch lease执行的受限HTTPS读取。任何未列能力均不存在，不通过配置、请求字段、Template声明、插件或“管理员模式”动态开放。
- Template、DesignDSL、Expression、Evaluator及RenderEngine全部禁止任意HTTP/DNS/socket、SQL/数据库、文件/目录、shell/process、脚本/eval/WASM、反射/classloading、环境变量、系统属性、凭证/token、模型/provider/付费调用、任意Clock/entropy注入、通用tool/plugin、发布/删除等业务mutation及跨scope数据访问。Connector只能在Template边界外先行归一化输入。
- Engine唯一外联是按RenderResource中短期Renderer-only lease访问canonical HTTPS allowlist；仍禁止caller URL/header、redirect、proxy、cookie、range、transparent compression、fallback、lease续签、替换URL/current、系统/built-in字体、GPU与跨请求credential/cache/state复用。
- unknown capability/member/Profile、Capability出现在非Expression-input位置、任意自报version/args或禁止面探测必须在状态建立、entropy/Clock读取、Resolver/fetch及任何mutation前hard fail。错误只返回稳定code和安全位置，不能回显环境、provider、URL、token、raw network error或证明隐藏对象存在。

### 7. 已冻结的输入、作者与展开结构预算

- 机器可读数值索引为[`capacity-budgets-v1.json`](../capacity-budgets-v1.json)，code/stage/reservation/zero-boundary索引为[`capacity-oracles-v1.json`](../capacity-oracles-v1.json)；两者共同构成planning evidence，不是调用方wire或独立可选Profile。所有计数在对应分组、去重、惰性剪枝或分配前按oracle声明原子预留，任何超限使用所属stable code并满足零写/零RenderDocument/零RenderOutput边界。
- RenderInput只接纳identity Content-Encoding的UTF-8 strict JSON body：entity最多`8 MiB`、depth `32`、单object `1,024` members、单array `10,000` items、总value/container `250,000`、单string `1 MiB UTF-8`、number token `256 bytes`、`customValues`在last-wins分组和unknown/PRIVATE消解前最多`256`项。压缩输入直接拒绝，不建立第二套decompressed预算。
- problem collection最多`200`项、单项canonical response最多`4 KiB`、集合最多`256 KiB`，其中始终为`PROBLEM_LIMIT_REACHED`预留`1 KiB`。普通problem最多使用`255 KiB`：自然结束且不超过200项时返回全部；出现第201项时丢弃第200个普通项并追加marker；普通项触及255 KiB时立即追加marker并停止昂贵检查。marker的closed reason为`ITEMS | BYTES`，字节边界先触发时使用`BYTES`；parser不安全时仍按既定单问题停止，任何路径均不得泄漏被省略内容。
- 单份DesignDSL最多`4,096` authored Nodes、authored tree depth `32`、单container children `1,024`、Definitions `512`、Bindings总数`4,096`且单Node `64`、单Text Runs `256`且总Runs `4,096`、Grid每轴tracks `64`、单TemplateUse fills `256`、单literal list `4,096`且全部literal list items合计`16,384`、全部authored Run text合计`1,000,000 Unicode scalars`。Polygon/Polyline point与Path command统一按一个vector entry计数，单Node `10,000`、全DSL `100,000`。
- Expression source单项最多`64 KiB UTF-8`且全DSL合计`1 MiB`；单Expression inputs `32`且合计`4,096`；单Mapping cases `256`且合计`8,192`；单Expression AST nodes `4,096`且合计`65,536`；Definition graph edges `8,192`、dependency chain depth `64`。这些限制在presence/lazy execution前施加，未使用input、未选择case和静态不可达Definition仍消耗静态预算。
- admitted decimal在移除不可观察尾零后的precision最多`128` digits、scale必须在`-64..64`；单次运算的不可观察intermediate最多`256` digits且scale在`-128..128`，任何可观察结果还必须回到admitted边界。`divide/round/formatDecimal`的literal scale只能是`0..64`；越界是Expression ERROR，不截断、饱和或改用binary floating point。
- closure最多`64` unique TemplateSnapshots、`256` authored TemplateRef edges、DAG depth `16`、全closure canonical DesignDSL bytes `32 MiB`；freeze最多`3`次完整attempt（首次加2次retry），每次漂移丢弃整轮。实际Template invocation最多`256`、invocation depth `16`、compositionViewport `256`。
- 每个实际Repeat occurrence的collection最多`1,000` items，Repeat nesting depth `8`，请求总Loop frames `10,000`。每个item在剪枝前预留frame与operation；第10,001个frame必须在创建前失败，不能把`1,000 × 1,000`静默截成部分结果。
- 请求总Render occurrences最多`25,000`、materialized static Nodes `20,000`、generated track/cell entries `100,000`、Evaluator logical operations `1,000,000`。memoization/cache不降低逻辑计数；retry另计physical attempt与deadline但不重置本次逻辑预算。
- RenderDocument-owned容量为canonical bytes最多`64 MiB`、strict JSON depth `128`、static Nodes `20,000`、child edges `19,999`、Runs `10,000`、text scalars `1,000,000`与vector entries `100,000`；它们在`DOCUMENT_SEAL`的capped writer/validator中、原子commit前失败，使用`RENDER_DOCUMENT_LIMIT_EXCEEDED`而非internal error。extended grapheme clusters `1,000,000`、shaped glyphs `2,000,000`、shaped lines/columns `100,000`、paint items `50,000`与clip depth `128`由Engine layout/shaping/raster阶段拥有。diagnostic sidecar最多`25,000` items/`8 MiB`；请求LayoutTrace时最多`20,000` items/`8 MiB`，超限按既定规则使整次请求失败而非截断trace或返回无trace图片。
- Canvas trim每轴必须`>0`且最多`1,000 mm`，bleed每边`0..100 mm`；任意authored geometry coordinate/length绝对值最多`10,000 mm`，font size为`>0..4,096 pt`，transform scale绝对值`0..100`，rotation为`-360..360 degree`且仍不作等价角归一化。通过物理数值域不保证给定DPI可Render，surface edge/pixel/bytes预算继续独立检查。

### 8. 已冻结的资源、运行与Renderer预算

- 每次closure admission最多`4,096` authored Asset occurrences与`512` unique logical Assets；实际Evaluation最多`2,048` resolve occurrences及一对一RenderResource entries、`128` unique exact contents。按occurrence累计声明raw bytes最多`2 GiB`、图片pixels最多`1,000,000,000`、FONT bytes最多`512 MiB`；按unique exact content累计分别为raw `256 MiB`、orientation后图片`125,000,000 pixels`、FONT `64 MiB`。单Asset的Acceptance Profile上限仍是IMAGE `64 MiB/20,000 edge/100M pixels`与FONT `32 MiB`，更低聚合先到先失败。
- request-local verified raw cache最多`256 MiB`、decoded RGBA8 cache最多`512 MiB`；cache hit不减少occurrence、lease、manifest、声明bytes/pixels或consumer-order预算。RenderResource manifest最多`4 MiB`，canonical fetch URL单项`2 KiB UTF-8`、合计`4 MiB`；包含成功与允许retry body在内的实际fetch bytes最多`512 MiB`。
- 完整closure静态capability sources最多`4,096`；逻辑demand总数`8,192`，其中Clock最多`4,096`、Random最多`4,096`。CapabilityCallPosition canonical bytes单项`2 KiB`、合计`16 MiB`，CapabilityState record最多`1 MiB`，result-digest streaming input最多`16 MiB`。初始化最多3次attempt；Random rejection固定最多128次。首次demand在求值前原子预留total与kind单位，Definition memo、alias重读或物理缓存不降低逻辑预算。
- effective output的DPI最大`600`，surface每轴最大`16,384 pixels`且总计最大`50,000,000 pixels`；RGBA8 surface因此最多精确`200,000,000 bytes`。Renderer working-set引用本节唯一的request-local decoded cache `512 MiB`定义，不建立第二个同名预算；decoder scratch最多`128 MiB`、encoder scratch最多`64 MiB`。单请求live RAM ceiling为`2 GiB`，取得FIFO queue position并成为accepted execution前必须原子预留，无法预留只可返回`RENDER_ENGINE_BUSY`。
- 完整PNG/JPEG image最多`512 MiB`；合法surface仍可能因实际encoded bytes超过该值而零输出失败。单请求ephemeral bytes最多`1 GiB`，reference实例总ephemeral为`4 GiB`并在接纳前设水位breaker。请求trace时，image `512 MiB` + trace `8 MiB` + multipart framing/header `64 KiB`形成精确multipart总上限`545,325,056 bytes`；任一part或总量超限均不得release图片。
- 从公共Render admission到atomic output seal的总deadline固定为`60 s`，阶段上限依次为admission+closure `5 s`、Evaluation+RenderDocument seal `15 s`、Engine queue wait `5 s`、resource `20 s`、layout+raster+encode `15 s`。阶段剩余时间不能借给另一阶段突破其上限，全部阶段还受同一不可延长absolute deadline；seal后的既有bytes transport可以越过deadline，但不能重新计算、续签或改变响应。
- 每个fetch最多2次attempt（首次加1次retry），固定无jitter backoff `100 ms`，单attempt最多`5 s`，且仍受resource `20 s`与总deadline约束；只有transport/5xx可retry。Command admission时每个lease expiry必须覆盖absolute deadline再加`5 s` safety margin，不足即在fetch前拒绝。
- cooperative checkpoint最坏间隔`50 ms`，成功接纳cancel后实际CPU/IO停止最多`250 ms`；不能满足50ms的不可中断primitive必须在其输入上证明最坏耗时不超限，否则拆分或拒绝。未seal的document/lease/resource buffer/raw sidecar/trace/temp在terminal或cancel后立即清理且最迟不超过deadline；最小terminal registry与已授权sealed response或安全terminal problem保留到`max(sealedAt, deadlineAt) + 5 min`，pre-command cancel tombstone保留`60 s`，CapabilityState/Resolver recovery record在原deadline后保留`5 min`。所有期限固定且不因访问、retry或cancel续期。
- Layout每请求最多`200,000` measure calls、`100,000` constraint-sensitive remeasure calls、`10,000,000` total layout operations、`8,000,000` shaping glyph attempts与`8,000,000` break candidates。最终glyph、line、node等仍同时受第7节较低输出计数；Text shrink的32次、Stack每容器`fillChildCount+1`轮和每条Grid span constraint单次处理全部计入总量。
- raster最多`200,000,000` painted pixel-visits，clip/mask与overdraw都计数；paint checkpoint chunk最多`262,144 pixel-visits`，fetch/decode/encode byte chunk最多`1 MiB`。FONT最多`32` unique exact contents、单FONT `256` tables且合计`4,096`，请求内unique glyph outlines最多`262,144`；更低raw/font/glyph预算仍共同生效。
- QR input的UTF-8 bytes最多`4 KiB`，随后仍按ECI26、error correction与version 1–40标准容量返回`CODE_CONTENT_TOO_LARGE`；Barcode保留既定fixed length/Code128 128 printable ASCII限制。请求内全部QR/Barcode module cells最多`5,000,000`，且每个码仍须通过transform、quiet-zone与integer pitch检查。

### 10. Canonical count、problem collection与accepted execution

- DesignDSL raw/token/parser hard limits先于完整model；安全结构、normalization与set sorting完成后，以16 MiB capped counting sink在任何dependency I/O前证明canonical-byte预算，随后才验证外部依赖并执行最终canonical emission/hash。counting与final writer必须重放同一exact canonical规则，前者不保留完整输出。
- problem collector固定预留1 KiB marker并按第7节算法处理items/bytes双上限；marker是显式集合截断事实，不是普通领域problem的替代品，也不得让验证器在达到上限后继续收集敏感或昂贵内容。
