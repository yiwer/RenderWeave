# Provider 生产合同请求包（ticket 06 执行资产）

用途：交给**有权代表签约主体的人**，向阿里云商务/法务取得 IMAGE_ONLY Schema Recognition 生产路线的书面合同权威。本包即取即用；任何一节得不到书面回答时的收口规则见末节。

## 执行红线（全程有效）

- 不发送真实或测试图片，不发起任何 Provider 调用（attempts = 0），不创建/读取/转述 API Key。
- 只接受书面形式：正式合同、DPA 附件、盖章/签署回复或可追溯的商务正式函件。**口头答复、控制台截图、营销页面、国际站 DPA 类推一律不得作为依据。**
- 问询与回复均保持 payload-free：只谈数据类别与处理条款，不附任何用户内容。

## 执行步骤

1. 明确候选路线：华北 2（北京）**业务空间专属按量付费 endpoint**——用户已于 2026-08-16 确认弃用 Token Plan（ticket 02 已证其禁止应用后端生产调用），首选标准按量付费模式（业务空间 API Key，区别于 Token Plan Key）。问询时以此精确产品/订单为对象。
2. 将下文《合同问题矩阵》整体发给阿里云商务/法务；A 节可由商务/解决方案架构师回答，B–G 节须法务/合规书面确认。
3. 收到书面回复后按「封存与登记约定」固化 identity/digest 并登记 J1。
4. 逐项对照「采纳标准」：任一必要项缺失、拒绝或含糊 → 记录 `PROVIDER_CONTRACT_NOT_ADMISSIBLE` 及缺失项清单，路线停止于此结论，不得降格采纳。

## 封存与登记约定

- **Identity**：`provider-contract/<签约主体>-<产品>-<yyyyMMdd>`；每份书面文件计算 domain-separated SHA-256 digest（`renderweave-provider-contract/1.0` + 文件字节），合同矩阵整体再算一次矩阵 digest。
- **存放**：原件位置以引用登记（合同编号/函件 identity），内容不复制进仓库；仓库只存 payload-free 的 identity、digest、采纳结论与缺失项清单。
- **到期/变更**：条款、endpoint、模型、价格、SLA 或处理政策任一漂移即触发准入撤销、drain 与重新认证（具体语义由 ticket 07 冻结）。
- **J1 记录**：签署人、签署时间、适用范围、exact 矩阵 revision digest、采纳/拒绝结论，追加到 map 的 Decisions-so-far 与本票 Answer。

## 收口规则

- 全部必要项书面齐备 → 在本票 `## Answer` 记录 identity/digest/J1，`Status: resolved`；ticket 07 随之解除阻塞。
- 任一必要项不可得 → 记录 `PROVIDER_CONTRACT_NOT_ADMISSIBLE` + 缺失项清单，`Status: resolved`（结论本身是合法终态）；后续路线选择回到 map 的 Not-yet-specified 重新评估。
- 供应商答复周期长的，每两周在本票 `## Comments` 追加一次 payload-free 进展（已发函/已收复/在审），不改 Status。
